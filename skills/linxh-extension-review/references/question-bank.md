# 澄清问题库

很多用户不会编程，问开放式问题（「你要不要本地后端」）他答不上。**全部用 A／B／C 选项 + 一句话权衡 + 推荐项** 的方式问。

## 使用规则

1. **不要把所有问题都问出来**：按需求归类后，只挑「AI 自己答不上」的关键缺口问，3-5 个上限。
2. **每个问题最多 3 个选项**：超过 3 个用户会嫌烦。
3. **每个选项必带「一句话权衡」**：用户要靠这一句话做选择。
4. **必带「推荐项」**：标 `推荐` 让用户知道默认走哪个。
5. **能默认就别问**：默认值都按 `extension-types.md` 的「形态建议」走。
6. **每次列完问题，固定加两行兜底**：
   - 「不确定？回『按推荐来』，我直接用推荐选项做。」
   - 「有别的想法？告诉我具体怎么改。」

## 问法模板

```
我要先问清 N 个点，每个点都给了推荐：

1、**问题简述**？
   A：选项一（一句话权衡）
   B：选项二（一句话权衡）推荐
   C：选项三（一句话权衡）

2、…

不确定？回「按推荐来」，我直接用推荐选项做。
有别的想法？告诉我具体怎么改。
```

## 通用问题（任何类型都可能问）

### Q · 触发方式

- A：打开页面自动跑（省一步操作，但容易误触发、占资源）
- B：点按钮主动跑（推荐：可控、不打扰）
- C：定时后台跑（最省事，但要常驻服务、有风控风险）

### Q · 用哪个账号

- A：你日常主号（推荐：能直接用浏览器现有登录态，但有封号风险）
- B：专门的小号（隔离风险，但要单独登录）
- C：不登录（公开数据，但抓不到详情）

### Q · 抓多少 / 跑多频

- A：当前页 / 单次（推荐起步，最小验证）
- B：当前对象全量（一个博主全部内容 / 整个列表）
- C：定时滚动 / 持续监控

### Q · 输出去哪

- A：直接下 .md / .json 到下载文件夹（推荐：零配置）
- B：推到在线表格（方便后续筛选）
- C：写本地数据库 / 上传服务器（适合大量数据 + 后续分析）

### Q · 通知怎么送（监控型必问）

- A：浏览器原生通知（最轻，但用户经常错过）
- B：聊天软件机器人推送（推荐：手机能收到）
- C：在插件图标上显徽章（被动看，不打扰）

## 采集型专属问题

### Q · 抓正文还是连图片视频一起

- A：只抓文字（推荐起步：最快验证链路通不通）
- B：文字 + 图片（图片要绕防盗链）
- C：文字 + 图片 + 视频（视频流量大，建议加大小阈值跳过）

### Q · 要不要评论 / 互动数据

- A：不要（推荐起步：评论接口往往要额外鉴权）
- B：要数字（点赞数 / 评论数 / 转发数，列表页就能拿到）
- C：要评论内容（接口单独打、容易触发风控）

### Q · 重复抓怎么处理

- A：按 URL 去重，已抓的跳过（推荐：增量更新最省事）
- B：每次全量覆盖（数据干净但浪费请求）
- C：每次新文件夹保存（适合做版本对比）

## 自动化操作型专属问题

### Q · 频率怎么控

- A：单次手动触发（推荐：最低风控）
- B：批处理排队（每隔 N 分钟随机间隔执行队列）
- C：定时任务（高风控、不推荐除非有小号）

### Q · 出错怎么办

- A：直接停（推荐：避免连续失败触发风控）
- B：重试 3 次（适合临时网络问题）
- C：跳过继续（仅适合大批量、单条不重要场景）

---

## UI 增强型专属问题

### Q · 增强的内容从哪来

- A：纯本地计算（推荐：零网络、零风控）
- B：被动监听页面已有请求（零额外风控）
- C：主动调外部 API（要走插件后台，注意跨域和 key 管理）

### Q · 注入位置

- A：固定位置（如顶部 / 底部，最稳）
- B：跟随某个元素（贴目标元素旁，需要兜底）
- C：浮动小窗（拖拽 / 折叠，推荐复杂面板用）

---

## 监控型专属问题

### Q · 状态变化的颗粒度

- A：只盯一种状态（在售 → 售罄、上线 → 下线，推荐起步）
- B：盯数值阈值（价格跌到 X、库存少于 Y）
- C：盯任何变化（任意字段变了都通知，噪音大）

### Q · 错过窗口期能不能接受

- A：能（每 5-10 分钟轮一次够用，最省）
- B：不能（要 < 1 分钟响应，必须接网站实时通道）
- C：极致实时（票务 / 秒杀级，建议直接外包给现成监控服务）

---

## 内容增强型专属问题

### Q · 用哪个翻译 / 改写源

- A：免费谷歌翻译（推荐起步：免费、够用）
- B：调 Claude / GPT 这类 AI API（质量好，但要管 API key、成本）
- C：本地大模型（零成本，但翻译质量比谷歌差一截）

### Q · 双语显示模式

- A：原文 + 译文换行显示（推荐：最易读）
- B：原文后面紧跟译文（省空间但拥挤）
- C：鼠标悬停才显示（最干净，但要交互）
