# 浏览器插件 5 大类型识别表

收到新需求时，先归到下面 5 类之一，再去看对应章节的「典型坑」和「形态建议」。一个需求可能跨两类，按主要诉求归类。

每一类末尾的「优先复用」会去 `reusable-assets.md`（或 `_personal-assets.md`）里按类型找对应已有项目。

---

## 类型 1 · 采集型（抓数据存本地）

**特征**：用户语言里有「抓 / 下载 / 存 / 导出 / 批量 / 归档 / 备份 / 爬」。

**典型例子**：抓某博主全部笔记、下载某视频字幕、把页面正文存 Markdown、批量保存图片。

**典型坑（前 3 个）**：
1. **鉴权 token 怎么拿**（说人话：网站会要个「签名码」才让你读数据）：很多平台详情接口要 token / signature，裸调直接拒绝。命门必须最先验证。
2. **懒加载 / 翻页**：现在前端都是滚动到底才加载下一段，要么模拟滚动、要么找到「下一页」接口的参数。
3. **频控 / 风控**：调太快会被限流甚至封号，得加随机间隔，别一口气怼一千条。

**风险评估默认**：封号风险 中（用自己登录的浏览器高频拉数据）／法律风险 低到中（看是不是公开内容）。

**优先复用**：你已有的「采集型」项目（参见资产清单），尤其是包含「登录态复用 + 按钮注入 + 本地服务」三件套的。

**形态建议**：
- 数据量小（< 50 条）：纯插件 + 浏览器本地存储 + 弹窗导出
- 数据量大 / 要落盘 / 要后处理：插件 + 本地后台小服务（用一个 187xx 段空闲端口）

## 类型 2 · 自动化操作型（替你点 / 替你填）

**特征**：用户语言里有「自动 / 一键 / 替我 / 帮我 / 模拟 / 批量发」。

**典型例子**：一键发推 + 配图、自动给某账号点赞、自动填表、文章一键导入富文本编辑器。

**典型坑（前 3 个）**：
1. **现代网站不接受程序直接点击**（React / Vue 这种）：你直接代码点按钮没用，必须用更接近真人操作的方式触发；输入框塞文字也不能直接赋值，要模拟「粘贴」。
2. **浏览器安全限制（CSP）**：很多页面不让插件直接连本地服务，需要让插件的「后台脚本」当中间人转发。
3. **平台风控最敏感**：自动化操作（发 / 关注 / 点赞）比纯采集封号风险高一档。

**风险评估默认**：封号风险 高（操作类被风控盯得最紧）。

**优先复用**：你已有的「自动化操作型」项目，尤其是包含「输入框塞文字三级兜底」「自动塞图」「点击事件兼容现代网站」的实现。

**形态建议**：
- 操作不留痕（只读 + 改本地显示）：纯插件
- 操作要留痕（发 / 关注）：必须配后台队列 + 速率控制，让脚本开机自动跑

## 类型 3 · UI 增强型（在页面上加东西）

**特征**：用户语言里有「显示 / 标记 / 高亮 / 提醒 / 徽章 / 加个按钮 / 加个面板」。

**典型例子**：推文上挂热度徽章、视频右侧显示弹幕密度、给商品挂历史最低价标签。

**典型坑（前 3 个）**：
1. **站内点链接 URL 变了但页面没刷新**：插件脚本不会重新跑，要专门监听 URL 变化再触发。
2. **目标元素被网站重渲染**：变量名一直变（哈希类名），CSS 选择器要找稳定锚点。
3. **嵌入位置容易跟原生 UI 抢空间**：要留好布局兜底。

**风险评估默认**：封号风险 极低（不发请求 / 只改本地显示）／维护风险 高（目标网站一改样式就废）。

**优先复用**：你已有的「UI 增强型」项目，尤其是包含「被动监听网页请求」「徽章注入模板」的实现。

**形态建议**：纯插件，零后台。

## 类型 4 · 监控 / 通知型（盯住某状态，变了告诉我）

**特征**：用户语言里有「监控 / 盯 / 提醒我 / 变了通知 / 上线了告诉我 / 跌到 XX 通知」。

**典型例子**：盯某商品降价、盯某博主发新内容、盯演唱会票务放出。

**典型坑（前 3 个）**：
1. **多久查一次的取舍**：太频被封、太慢错过窗口。能用网站现成的实时推送通道比定时查询好。
2. **通知怎么送达**：浏览器原生通知用户经常看不见，建议接外部 IM（聊天软件）的机器人推送。
3. **后台运行限制**：纯插件后台脚本休息一会就被浏览器停掉，长任务必须配本地常驻服务。

**风险评估默认**：封号风险 中（看查询频率）／可靠性风险 高（漏报代价大）。

**优先复用**：你已有的「监控型」项目，尤其是包含「被动监听网页请求」「开机自启常驻服务」的实现。

**形态建议**：
- 能被动接收目标网站请求（推特、电商类）：纯插件，零后台
- 必须主动定时查询：插件 + 本地服务 + 自动重启守护 + 外部 IM 推送

## 类型 5 · 内容增强 / 转换型（改写 / 翻译 / 格式化）

**特征**：用户语言里有「翻译 / 改写 / 总结 / 转格式 / 美化 / 在原文旁边显示」。

**典型例子**：双语翻译注入、把页面正文转 Markdown 复制、英文论文摘要、代码片段加注释。

**典型坑（前 3 个）**：
1. **逐字处理还是整段处理**：拿大段当单位会漏，必须按文本节点级走 + 标记已处理避免重复。
2. **样式注入冲突**：双语模式排版怎么搞、要不要保留原格式，是工作量最大的隐藏点。
3. **网站套网站（iframe）**：很多页面有内嵌子页面，要让插件在子页面里也能跑。

**风险评估默认**：封号风险 极低／法律风险 看翻译源（自调用免费翻译 OK，转发付费 API 内容要注意）。

**优先复用**：你已有的「内容增强型」项目，尤其是包含「双语注入排版」「逐字节点去重」「优雅降级」的实现。

**形态建议**：纯插件，调外部 API 走插件的后台脚本（避开跨域限制）。

## 跨类型公共法则

- 涉及需要登录的网站：先确认你的登录态在浏览器的哪个用户配置里（默认 Default，有些网站可能在别的 Profile）。
- 选后台服务端口：避开本机已被占用的端口，默认在 187xx 段（如 18785、18791）挑空闲的。
- 开机自动起服务：用系统自带的开机自启机制（macOS launchd / Windows 任务计划），要确保自启时能找到必要的命令路径。
- 任何要联网调代理的：先取当前活跃的代理端口，别在代码里写死。
